# دستیار هوشمند PeDitX-AI برای Linux

یک دستیار Linux با CLI و رابط انگلیسی دسکتاپ برای اتصال به API سازگار با OpenAI Chat Completions. رابط گرافیکی مخصوص GNOME است؛ روی سیستم headless مثل Raspberry Pi Lite و OpenWrt نسخهٔ CLI استفاده می‌شود. سرویس مرورگر دسکتاپ فقط روی `127.0.0.1` گوش می‌دهد.

## نصب در Mint، Ubuntu یا Debian

```bash
cd /media/peditx/HDD/Workspace/PeDitX-AI
bash install.sh
```

نصب‌کننده هدف را تشخیص می‌دهد: Mint/Ubuntu/Debian را با `apt` برای GNOME یا CLI آماده می‌کند و OpenWrt/PeDitXOS را جداگانه با `apk` (نسخه‌های جدید) یا `opkg` و بسته‌های `.ipk` (نسخه‌های قدیمی) به CLI می‌برد. روی OpenWrt فایل‌های GNOME نصب نمی‌شوند. روی Raspberry Pi OS Lite هم نسخهٔ CLI نصب می‌شود.

در GNOME از منوی برنامه‌ها «PeDitX-AI Desktop» را اجرا کن. در نسخهٔ headless دستور `assist` را بزن. آدرس پایهٔ API (مثلاً `https://server.example/v1`)، نام مدل و کلید را در Settings رابط دسکتاپ یا از CLI وارد کن. کلید در مسیر XDG config و گفتگوها در مسیر XDG state ذخیره می‌شوند؛ می‌توانی با `XDG_CONFIG_HOME` و `XDG_STATE_HOME` محلشان را عوض کنی. گفتگوهای ذخیره‌شده را در رابط یا CLI ادامه بده.

در رابط دسکتاپ، انتخاب مدل، سطح دسترسی سیستم‌عامل (محدود، برنامه‌ریزی، پرسش پیش از هر اقدام، یا کامل) و میزان Thinking زیر کادر گفتگو قرار دارد و میانبر Settings هم همان‌جاست. جهت پایهٔ رابط با زبان مرورگر هماهنگ می‌شود؛ عربی و فارسی RTL و ترکی و چینی LTR هستند. جهت هر پیام گفتگو هم جداگانه از متن تشخیص داده می‌شود؛ این تغییر، چیدمان را پشتیبانی می‌کند و ترجمهٔ همهٔ برچسب‌های رابط هنوز جداگانه باید انجام شود. Thinking روی حالت Auto به پیش‌فرض مدل می‌ماند؛ سطح‌های Low/Medium/High به‌صورت `reasoning_effort` فرستاده می‌شوند و فقط روی API/مدل‌های پشتیبان اثر دارند.

## Workspace و فایل‌های پیوست

در صفحهٔ اصلی مسیر Workspace انتخاب‌شده دیده می‌شود و از همان‌جا می‌توان آن را عوض کرد. پوشهٔ پیش‌فرض `~/PeDitX-AI-Workspace` است؛ مسیر یک پوشهٔ جداگانه از تنظیمات خصوصی برنامه و فایل‌های سیستم است. می‌توانی مسیر یک SMB share از قبل mountشده را انتخاب کنی یا از دستیار بخواهی روی دسکتاپ GNOME آن را با پنجرهٔ امن سیستم mount کند. رمز فقط در پنجره/کلیدنگهدار سیستم وارد می‌شود و برنامه آن را دریافت نمی‌کند. در سیستم headless یا OpenWrt ابتدا share را در خود سیستم mount کن و بعد مسیرش را به‌عنوان Workspace بده. در حالت محدود، ابزارهای خواندن فایل به Home و Workspace انتخاب‌شده محدودند؛ پوشه‌های حساس مثل `.ssh` همچنان مسدودند. Workspace خودکار اسکن نمی‌شود.

از کنار کادر پیام می‌توان تصویر، فایل متنی، PDF، DOCX و ODT پیوست کرد. متن سندها روی دستگاه استخراج می‌شود و همراه همان پیام به endpoint مدل انتخابی فرستاده می‌شود؛ تصاویر هم با پیام ارسال می‌شوند. PDF به ابزار `pdftotext` از بستهٔ `poppler-utils` نیاز دارد. برای فایل‌هایی که پشتیبانی نمی‌شوند، آن‌ها را در Workspace بگذار و از PeDitX-AI بخواه با دسترسی فعلی همان مسیر را بررسی کند.

## استفاده در موبایل و نصب به‌شکل PWA

رابط روی صفحهٔ کوچک واکنش‌گراست: تاریخچه از دکمهٔ منو باز می‌شود، پیام‌ها داخل پنل چت اسکرول می‌شوند و کادر پیام پایین صفحه می‌ماند. رابط از PWA هم پشتیبانی می‌کند. در Android دکمهٔ Install app یا گزینهٔ Install مرورگر را بزن؛ در iOS از Share → Add to Home Screen استفاده کن. آیکن‌های نصب از لوگوی اصلی PeDitX-AI ساخته شده‌اند. برای جلوگیری از ذخیرهٔ توکن و تاریخچه در cache، برنامه فقط آنلاین کار می‌کند.

سرویس فعلی فقط روی همان دستگاه و نشانی 127.0.0.1:8765 گوش می‌دهد؛ نصب PWA به‌تنهایی اتصال iPhone یا Android به رایانه را برقرار نمی‌کند. دسترسی گوشی به سرویس رایانه به مسیر امن جداگانه با HTTPS یا VPN و احراز هویت نیاز دارد؛ پورت برنامه روی شبکه باز نمی‌شود.

## هویت، حافظه و Skills

چهار فایل محلی در `~/.config/peditx-ai/instructions/` نگه‌داری می‌شوند: `personality.md`، `user.md`، `memory.md` و `long-term-memory.md`. `user.md` پروفایل کوتاه کاربر است؛ `memory.md` ترجیحات کاری و زمینهٔ پروژه‌های جاری را نگه می‌دارد؛ و `long-term-memory.md` برای هدف‌ها و واقعیت‌های ماندگار است. جزئیات گفتگو فقط برای پاسخ همان گفتگو استفاده می‌شود و خودکار ذخیره نمی‌شود. PeDitX-AI فقط وقتی کاربر صریحاً می‌خواهد چیزی درباره‌اش به خاطر سپرده شود، حافظه را تغییر می‌دهد و می‌گوید چه چیزی ذخیره کرده است. اطلاعات این فایل‌ها و Skill مرتبط در هر درخواست به API انتخابی فرستاده می‌شوند؛ برای داده‌های حساس از حافظه استفاده نکن. پروفایل نصب تازه خالی است و اطلاعات شخصی از پیش در آن قرار نمی‌گیرد. فایل‌ها از Settings قابل مشاهده و ویرایش هستند.

مهارت‌ها از قالب Claude Code یعنی پوشهٔ جداگانه با `SKILL.md` و frontmatter شامل `name` و `description` استفاده می‌کنند و در `~/.claude/skills/` نصب می‌شوند. از Settings می‌توان مخزن Git را جست‌وجو، یک مهارت را نصب یا حذف کرد. بخش remote برای همگام‌سازی فایل‌های شخصیت، حافظه و مهارت‌ها با مخزن Git خصوصی است؛ Git از SSH agent یا credential helper سیستم استفاده می‌کند.

## توسعهٔ مستقل

منبع PeDitX-AI از اسکریپت تم جداست و در این ساختار نگه‌داری می‌شود:

- `src/peditx_ai.py`: هسته، CLI، سرویس محلی، ابزارها و حافظه
- `web/index.html`: رابط گرافیکی
- `assets/peditx-ai.png`: لوگو
- `docs/`: معماری و تصمیم‌های انتشار
- `install.sh`: انتخاب‌کنندهٔ نصب بر اساس سیستم‌عامل
- `install/gnome-desktop.sh`: نصب رابط و میانبرهای مخصوص GNOME
- `install/debian-headless.sh`: نصب CLI برای سیستم‌های Debian بدون دسکتاپ
- `install/openwrt.sh`: نصب CLI با `opkg` یا `apk`

برای اجرای نسخهٔ سورس:

```bash
cd /media/peditx/HDD/Workspace/PeDitX-AI
PYTHONPATH=src python3 -m peditx_ai
```

### هدف پشتیبانی از Raspberry Pi و OpenWrt

نصب GNOME در `install/gnome-desktop.sh` مستقل است. `install.sh` روی Debian/Ubuntu نصب دسکتاپ یا CLI headless را انتخاب می‌کند و روی OpenWrt به `install/openwrt.sh` می‌رود. نصب OpenWrt با `opkg` یا `apk` وابستگی‌های حداقلی Python را می‌گیرد و فقط CLI برای SSH می‌گذارد؛ GNOME و سرویس وب شبکه‌ای نصب نمی‌شوند. بستهٔ بومی OpenWrt برای انتشار و سرویس procd هنوز مرحلهٔ بعدی‌اند. برنامه Python 3.10 یا جدیدتر می‌خواهد. روی OpenWrt معمولاً CLI با کاربر root اجرا می‌شود؛ پس حالت full یعنی دسترسی root. جزئیات در `docs/platform-support.md` است.

برای اجرای bootstrap روی روتر، پوشهٔ پروژه را به روتر منتقل کن و نصب را از SSH اجرا کن:

```bash
scp -r PeDitX-AI root@ROUTER:/tmp/
ssh root@ROUTER 'cd /tmp/PeDitX-AI && sh install.sh'
```

این دستور روی روتر نصب را انجام می‌دهد؛ اسکریپت خودش چیزی از اینترنت دانلود نمی‌کند، به‌جز فهرست‌ها و بسته‌هایی که package manager رسمی OpenWrt نصب می‌کند. مخزن بستهٔ Python باید برای همان نسخه و معماری روتر فعال باشد. نصب‌کننده فضای خالی واقعی root/extroot را نمایش می‌دهد و حد اجباری از پیش تعیین نمی‌کند؛ package manager با اندازهٔ واقعی بسته‌ها تصمیم می‌گیرد نصب جا می‌شود یا نه.

برآورد اولیه برای پروفایل CLI حدود ۸ تا ۱۵ مگابایت فضای نصب‌شده است: فایل هسته حدود ۴۴ کیلوبایت است و بخش عمدهٔ حجم مربوط به Python، پشتیبانی UTF-8 و HTTPS است. این عدد تخمینی است و با نسخه و معماری OpenWrt فرق می‌کند. تاریخچه جداگانه رشد می‌کند: هر گفتگو حداکثر ۴ مگابایت و تا ۵۰ گفتگو نگه‌داری می‌شود.

بعد از نصب، از SSH تنظیم API را امن و تعاملی انجام بده و گفتگو را شروع کن:

```bash
assist --configure
assist
```

کلید API هنگام ورود روی صفحه نمایش داده نمی‌شود و در فایل config خصوصی حساب فعلی ذخیره می‌شود. در نصب OpenWrt فقط فایل هسته و CLI نصب می‌شود؛ HTML، لوگو و نصب‌کنندهٔ GNOME به روتر کپی نمی‌شوند.

نصب‌کنندهٔ یک‌کلیکی تم هنوز نسخهٔ فعلی خودش را دارد. بعد از نهایی‌شدن توسعه، اتصال آن به PeDitX-AI به‌شکل یک گزینهٔ نصب جداگانه خواهد بود که `PeDitX-AI/install.sh` را اجرا می‌کند؛ سورس برنامه داخل اسکریپت تم کپی نمی‌شود. جزئیات در `CONTRIBUTING.md` و `docs/architecture.md` است.

## اتصال SSH و SMB

برای SSH، نام میزبان یا alias تعریف‌شده در `~/.ssh/config` را در درخواستت مشخص کن. برنامه از OpenSSH، کلیدهای موجود، SSH agent و host key تأییدشدهٔ سیستم استفاده می‌کند؛ کلید خصوصی یا رمز را از تو نمی‌گیرد و بررسی host key را غیرفعال نمی‌کند. در حالت محدود فقط اطلاعات سیستم و فایل‌های مشخص‌شده را می‌خواند. در حالت با اجازه، هر عملیات SSH قبل از اجرا تأیید می‌خواهد؛ حالت کامل اجازهٔ اجرای فرمان و نوشتن روی میزبان‌های مشخص‌شده را می‌دهد. خروجی ابزارهای راه‌دور برای پاسخ‌دهی به API مدل انتخابی فرستاده می‌شود، پس فقط فایل‌ها و اطلاعات مرتبط با درخواست را بررسی کن. اسکن شبکه یا جست‌وجوی خودکار میزبان‌ها انجام نمی‌شود.

برای SMB روی GNOME، نام server و share را بده تا سیستم آن را با GIO mount کند؛ سپس مسیرش Workspace می‌شود. روی headless/OpenWrt share را از خود سیستم mount کن و مسیر mountشده را انتخاب کن.

## سطح دسترسی

- **محدود:** اطلاعات سیستم و فایل‌های خانگی و Workspace و جزئیات SSH مشخص‌شده را می‌خواند؛ اجرای فرمان و نوشتن فایل غیرفعال است.
- **برنامه‌ریزی:** منابع مرتبط را می‌خواند و یک طرح مرحله‌به‌مرحله می‌دهد؛ هیچ فرمان، تغییر فایل/تنظیم یا mount اجرا نمی‌کند تا سطح دسترسی را عوض کنی.
- **با اجازه:** هر ابزار/فرمان قبل از اجرا در پنجرهٔ تأیید مرورگر نشان داده می‌شود. اجرای فرمان به فهرست فرمان‌های تکی و کم‌خطر محدود است؛ برای فرمان پیچیده، تغییر‌دهنده یا نصب بسته از حالت کامل استفاده کن.
- **کامل:** فرمان دلخواه و نوشتن فایل روی همین دستگاه و میزبان‌های SSH که صریحاً نام برده‌ای بدون تأیید جداگانه انجام می‌شود. این دسترسی روی هر میزبان با همان حساب SSH برقرارشده اجرا می‌شود. رمز sudo ذخیره نمی‌شود و برنامه آن را دور نمی‌زند.

در هر حالت، نوشتن فایل نسخهٔ قبلی را کنار فایل با پسوند `.peditx-ai-backup` نگه می‌دارد. محدودیت دسترسی ابزارها جایگزین اعتماد به مدل/سرور نیست: در حالت کامل، هر فرمانی که مدل برگرداند می‌تواند اجرا شود. فقط مدلی را به این حالت وصل کن که به آن اعتماد داری.

## توقف و حذف

از دکمهٔ **Stop** در رابط یا `Ctrl+C` در ترمینالی که برنامه را اجرا کرده، سرویس محلی را ببند. برای حذف برنامه، `~/.local/share/peditx-ai/`، `~/.local/bin/peditx-ai`، `~/.local/bin/assist`، `~/.local/share/applications/peditx-ai.desktop` و آیکون `~/.local/share/icons/hicolor/512x512/apps/peditx-ai.png` را حذف کن. برای حذف کلید ذخیره‌شده، فایل `~/.config/peditx-ai/config.json` را حذف کن.

## استفاده از CLI

پس از نصب، در Kitty/Zsh یا هر ترمینالی:

```bash
assist
```

این فرمان گفت‌وگوی تعاملی را در ترمینال باز می‌کند و گفتگوها را برای ادامه در اجرای بعدی ذخیره می‌کند. برای یک درخواست مستقیم:

```bash
assist "Summarize my GNOME setup"
```

مدل‌ها را فهرست کن یا یکی را انتخاب کن:

```bash
peditx-ai --models
assist --choose-model
```

سطح دسترسی ذخیره‌شده را از ترمینال عوض کن:

```bash
assist --mode observe
assist --mode plan
assist --mode ask
assist --mode full
```

حالت `plan` فقط بررسی می‌کند و طرح می‌دهد. برای فعال‌کردن `full` باید واژهٔ `FULL` را تأیید کنی. همین تنظیم برای رابط گرافیکی و CLI مشترک است. در حالت `ask`، CLI پیش از هر ابزار ازت اجازه می‌گیرد.

## محدودیت نسخهٔ اول

این رابط، API سازگار با Chat Completions را می‌خواهد؛ APIهای اختصاصی Responses/Anthropic پشتیبانی مستقیم ندارند. کلید در فایل محلی با مجوز خصوصی ذخیره می‌شود، نه در GNOME Keyring. عملیات گرافیکی GNOME فقط از طریق ابزارهای CLI قابل‌دسترسی انجام می‌شوند.
